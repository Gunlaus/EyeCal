# Architecture

## Application structure

- `src/app` owns SDL initialization, keyboard input, fullscreen mode changes and redraw scheduling. It uses a steady clock to refresh HDR detection.
- `src/vk` owns the surface, graphics queue, SDR swapchain, rendering and presentation. It chooses a Vulkan 1.3 device with dynamic rendering and a queue family that supports both graphics and presentation. One graphics frame can be in flight. Acquire synchronization is reused after the graphics fence and the present-wait semaphore is indexed by swapchain image.
- `src/ui` lays out the guide, reserved text areas and the test region. It draws an embedded signed-distance glyph atlas in Vulkan. Its fragment shader blends text with a high-contrast panel. The atlas uses 12 × 20 cells with two bits per distance sample and is generated by `assets/font/bake_font.py`. Builds embed the checked-in atlas and the SPIR-V generated by `glslc`. Python and Pillow are needed only to rebake the font.
- `src/platform` isolates Win32, DXGI and Vulkan Win32 fullscreen extensions. A portable implementation reports output color as unknown and uses ordinary Vulkan presentation.
- `tests` covers SDR format selection, pixel extent and image count with doctest. A CTest source scan rejects Vulkan sRGB image-format identifiers in app and shader sources.
- `src/guide` parses the embedded English JSON at startup and validates the screen definitions. Its session model tracks the current screen, answer selections, menu state, text size and preview dither. Layout measures the available pixel area before drawing text and the preview.
- `src/patterns` contains the Vulkan ramp draw and the C++ quantization reference. Pattern shaders include `shaders/include/quantize.glsl` and call its shared quantizer after producing display-encoded values. The M2 ramp uses an explicit seed of zero and stays static across redraws.

The accepted swapchain pairs use BGRA8 or RGBA8 UNORM with `VK_COLOR_SPACE_SRGB_NONLINEAR_KHR`, the SDR presentation color space. The attachment stores nonlinear code values directly. It performs no image-format sRGB conversion, application color management, or resizing. FIFO is guaranteed by Vulkan. The app renders in response to input and surface events.

The borderless mode follows the OS desktop resolution. M1 uses the SDL window's physical pixel extent and refuses swapchains whose fixed surface extent disagrees. A user-selected non-native desktop mode, GPU scaling and overscan can still affect the physical display. Set the desktop to the recommended mode before calibration. There is no mode switch at launch.

F11 first asks SDL for a fullscreen display mode with the same physical pixel dimensions as the desktop. Where the Vulkan Win32 extension is supported, the app queries fullscreen support for the target monitor and requests application-controlled exclusive presentation. If Vulkan exclusive acquisition fails, the SDL mode may remain active and F1 reports the fallback. F11 restores borderless presentation. The swapchain is rebuilt on pixel-size changes, display changes and loss of exclusive mode.

Windows HDR detection uses the DXGI output description for the window's monitor. It returns SDR, HDR or unknown, and refreshes from a new factory when the window or display changes and periodically while idle. This platform query can support a future HDR presentation path without exposing native APIs to the renderer. The M1 renderer always selects SDR.

The Windows target statically links SDL3, volk and the compiler's redistributable C/C++ runtime. SDL supplies the Vulkan loader function from the system driver installation. The executable includes the shader bytecode, glyph data and the English screen text and an in-app notice viewer. CMake dependency downloads and SDK acquisition occur at build time.


## Screen 6c bit-depth probe design

Screen 6c will compare the identical no-dither ramp at 8-bit and 10-bit on the same display. Record the successfully presented swapchain format, output monitor, extent, and granted Vulkan exclusive state separately for each observation. The exclusive state comes from the same successful acquisition flag shown by F1. Pressing F11 or switching the display mode alone does not establish that state. Invalidate the observation on a display or mode change, exclusive loss, or unsuccessful presentation. Capture a new observation after recovery.

| Observations | Result copy or next action |
| --- | --- |
| The surface cannot present a 10-bit UNORM swapchain | “10-bit comparison unavailable.” |
| Either completed pass lacked granted Vulkan exclusive presentation | “Inconclusive in borderless mode.” Explain that windowed composition can affect effective precision and propagation from a Vulkan 10-bit swapchain is unverified. This includes an SDL fullscreen mode switch with Vulkan exclusive acquisition denied. |
| Both passes were exclusively presented at matching extents on the same output, and 10-bit looked smoother | “10-bit looked smoother on this display.” |
| Both passes meet those conditions, and the user observed clear banding with no improvement at 10-bit | “The chain may be truncating to 8-bit somewhere.” List the GPU, driver, cable and display as possible contributors. |
| The user saw no banding to compare, was unsure, or the two passes are otherwise incomparable | “Inconclusive.” Offer to repeat the comparison. |

Only a paired, exclusive observation can produce wording about likely truncation. Exclusive presentation still provides no measurement of transport or panel depth. See [the Windows composition findings](VERIFIED.md#automatic-colour-management-and-10-bit-comparisons).
